# 远程 Issue #37 / #36 / #41 落地计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans（inline 执行）。Steps use checkbox (`- [ ]`) syntax for tracking。

**Goal:** 把三个已评审的 open issue 落成可执行扩展工件：#37 定时任务/批处理窄口径扩展、#36 独立对账扩展、#41 IM 协作触达层扩展；核心六类契约不改。

**Architecture:** 三份独立扩展包，各自一个分支一个 PR。`scheduler` 为 `kind: runtime`（自带 DDL + 参考实现 + CI 冒烟）；`reconciliation`、`im` 为领域扩展（对象 Schema → `schema-compiler` 生成 DDL，命令处理器注册于 `handlers.py`，场景用例由参考内核执行）。每份扩展配一份 ADR 记录边界与不做项。

**Tech Stack:** Python 3.10+（stdlib + PyYAML + jsonschema）、PostgreSQL 16、JSON Schema 2020-12、OpenAPI 3.1。

**Spec:** issue #37 / #36 / #41 的评审结论（byteforce-cn 2026-10-21 / 2026-10-27 评论）、ADR-0012 §4.2；`extensions/README.md`（扩展结构/权限目录/跨扩展前置）、`01-data-contract/object.schema.json`、`02-operation-contract`（命令/查询）、`05-audit-contract`。

## Global Constraints

- `main` 受保护：分支 → PR → CI 全绿 → `--squash` 合并 → 删分支；一个 issue 一个 PR。
- 核心契约（01–06）零改动；扩展不得占用 `EIS-` 错误码前缀。
- 每个任务结束 `python3 tools/e2e-runner --all` 必须全绿；新增用例后同步计数口径（README/CONTRIBUTING/CHANGELOG 中 155 等数字）。
- 不写锁算法/选主/cron 解析器/实时传输层；只规定可观察执行语义。
- 测试确定性：不依赖真实时钟/网络；DDL 断言放 `tools/ci/*.sql`，由 CI PostgreSQL 16 执行。

## Review Focus

- **run_key 幂等**：同一计划时点重复发起不得产生第二份 run；重跑必须显式换 `sequence`（reconciliation）或由调度器判定 `skipped`。
- **租约抢占**：过期租约可被抢占，旧持有者以过期 `lease_id` 写入必须被拒，而不是靠锁本身。
- **撤回/移出群/解散**：一律追加版本（`version+1`）且写审计；不得状态翻转后不留痕。
- **查询面**：读接口使用 `as_of` / `recorded_as_of` / `min_version`，扩展序列参数（`serverSeq`/`sinceSeq`）标注为非核心查询语义。
- **payload 大对象**：二进制/大内容用 `content_sha256` + `content_ref` 外置，不塞业务行。
