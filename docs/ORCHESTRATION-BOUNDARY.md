# 编排边界（Orchestration Boundary）

> **文档性质：informative（不构成合规等级，不得作为 MUST 验收）**。
> 归属：实现与运维层（ADR-0012 三层判据；issue #35 裁决）。
> 本文说明「跨聚合长流程」在 EIS 之外如何编排；EIS 核心不提供 Saga/TCC 执行引擎。

## 1. 结论先行

- EIS 的射程是六类元结构（对象/命令/时间/授权/审计/演进）；**编排引擎不是契约**。
- 若需要跨聚合长流程，执行器外置（如 coord workflow），EIS 只提供可被编排调用的命令与可读状态。
- 本文不是第二权威：命令语义、幂等、审计仍以 `02-operation-contract` / `05-audit-contract` 为准。

## 2. 与 EIS 的接缝

| 接缝 | 要求 |
|------|------|
| 业务步骤 | 每个步骤仍是一条 EIS 命令：必须有 `idempotency_key`，不得由编排器直写业务表 |
| 幂等 | 编排重试必须复用同一 `idempotency_key`（同载荷）；换键重试等于新命令 |
| 审计 | 编排实例 ID 进入命令的 `targets`/事件 `subjects`（长流程命令可用流程实例 ID 作为 `locator`，ADR-0014），使审计链可按流程追溯 |
| 部分完成 | 流程的部分完成状态必须能在查询面读到（对象状态/流程状态），不得只存在于编排器内存 |
| 补偿 | 补偿 = **反向命令**（例如取消/冲正），自身必须幂等、可重放、受审计；不得直接改库或删审计 |
| 编排状态 | 编排实例表由执行器拥有；EIS 不定义其 Schema，也不把它当业务对象 |

## 3. 推荐形态（非强制）

1. **命令化步骤**：编排器只做「调用命令 + 读状态 + 决定下一步」，不复制领域规则；
2. **幂等键生成**：`flow_id + step_id` 作为幂等键种子，重试稳定复现；
3. **状态机外置**：流程状态机由执行器维护；领域对象状态机仍由属主域命令维护；
4. **失败分类**：可重试（超时/临时不可用）用同键重试；不可重试（业务拒绝）走补偿/人工；
5. **超时/重试策略**：由执行器配置，**不进 EIS 契约**；
6. **部分完成可见**：每个已完成步骤的结果必须落成对象/事件，查询面可重建流程进度；
7. **补偿顺序**：逆序补偿；补偿命令的幂等键同样稳定；补偿失败必须可观测、可重试。

## 4. 明确不做

- EIS 不内置 Saga/TCC 执行引擎（避免与 coord workflow 形成第二权威）；
- EIS 不定义流程 DSL、步骤编排格式、超时/重试/选主策略；
- EIS 不承诺跨聚合事务的原子性；一致性由「命令 + 补偿 + 幂等」达成最终一致；
- 编排器不得绕过命令直接写业务表、不得修改审计链。

## 5. 可验证的落地建议（非契约）

- 用 `tools/e2e-runner` 的 `kind: scenario` 覆盖：步骤成功 → 补偿 → 审计链 valid；
- 用命令响应 `locator/version`（ADR-0014）与读接口 `min_version`（ADR-0017）校验写后读一致性；
- 用 `tools/audit-verifier` 验证补偿步骤也进入审计链；
- 编排实例 ID 的贯通性用事件 `subjects`/审计条目人工抽查（当前无自动化 lint）。
